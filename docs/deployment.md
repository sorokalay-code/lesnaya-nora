# Публикация на GitHub Pages

Адрес игры: https://sorokalay-code.github.io/lesnaya-nora/

## Однократная настройка

1. Откройте репозиторий `sorokalay-code/lesnaya-nora` под аккаунтом с правами администратора.
2. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**.
3. Отправьте изменения в `main`. В **Actions → Проверка и публикация игры** дождитесь успешных задач `build` и `deploy`. При необходимости запустите workflow вручную через **Run workflow** для `main`.

Workflow публикует только проверенный каталог `dist`. Pull request запускает проверки без публикации. Отдельная ветка `gh-pages`, секреты и персональные токены не нужны. Используется штатный временный `GITHUB_TOKEN`.

## Обычный цикл обновления

```powershell
pnpm install --frozen-lockfile
pnpm run check
git add .
git commit -m "Описать изменения игры"
git push origin HEAD:main
```

Push в `main` автоматически пересобирает весь проект и публикует код, модели, текстуры и звуки. Фильтров по каталогам в workflow нет. Если проверки упадут, опубликованная версия остаётся прежней. Каталог `dist` не коммитится. Зависимости обновляются через `pnpm add` вместе с `pnpm-lock.yaml`.

## Ресурсы и кэш

- Статические ресурсы размещаются в `public/models`, `public/textures`, `public/sounds` и других подкаталогах `public`. Vite копирует их в сборку автоматически.
- Текстуры почвы и сезонные атласы рельефа и декоративных растений генерируются командой `pnpm exec tsx tools/build-terrain-textures.ts`. В сезонном атласе земли десять вариантов. В атласе покрова к десяти сезонным растениям добавлены 20 спрайтов лесного декора и пять вариантов летней высокой травы. PNG из `public/textures` коммитятся вместе с генератором.
- В коде получайте URL через `assetUrl('sounds/bird.ogg')` из `src/game/AssetPaths.ts`. Не используйте абсолютные пути `/models/...` или `/sounds/...`: Pages размещает игру в подкаталоге.
- Для нового вида модели дополните реестр `MODEL_NAMES`, а для анимируемого существа — `CREATURE_NAMES` и предоставьте основной GLB и `-low.glb`. GLB следует экспортировать самодостаточным, со встроенными ресурсами. Обновлённый реестр проверяется при каждой сборке.
- Существующие модели создаются командой `pnpm run models`. После изменения генератора выполните её локально и закоммитьте результаты из `public`. CI намеренно не перегенерирует модели, чтобы не затереть вручную подготовленные GLB и текстуры.
- Для выборочной генерации передайте имена: `pnpm run models -- spider rock_granite rock_moss rock_slate`. Создадутся только указанные GLB (и LOD существ); остальные модели и PNG не изменятся. Исходники камней и паука находятся в `tools/art/WildAssets.ts`.
- Модель кролика обновляется выборочно через `pnpm run models -- rabbit`: оба LOD создаются из функции `rabbit` в `tools/build-models.ts`. Объём задних лап задают корпус и анимируемые конечности; отдельные светлые сферы на бёдрах удалены. После изменения добавляйте в коммит `rabbit.glb` и `rabbit-low.glb`.
- Команда `pnpm run models -- oak pine spruce larch birch maple ash aspen linden rowan` обновляет модели деревьев и соответствующие текстуры `public/textures/*-foliage.png`. Кроны состоят из закреплённых плоскостей с альфа-отсечением. Коммитьте модели и текстуры вместе.
- `asset-manifest.json` содержит SHA-256 каждого файла. Общий хеш ресурсов добавляется к URL загрузчика, поэтому замена файла с прежним именем меняет его URL. JS/CSS получают хеши Vite. Уже открытая игра использует загруженную версию до перезагрузки вкладки.
- `check:deploy` сверяет наличие и содержимое всех ресурсов в `dist`, версию манифеста и пути HTML. Проверяется отсутствие незагруженных указателей Git LFS.
- Звуки пока синтезируются через Web Audio. Новые аудиофайлы загружайте через `assetUrl`; запуск звука должен оставаться после действия пользователя из-за правил браузера.
- Паук-прыгун зарегистрирован как `jumping-spider` в фабрике и реестре моделей. Обе модели (`jumping-spider.glb` и `jumping-spider-low.glb`) публикуются и проверяются вместе с остальными ресурсами. При изменении походок повторно генерируйте GLB затронутых видов: исходники TypeScript сами по себе не обновляют встроенные анимации.

## Локальная проверка публикации

```powershell
pnpm run build
pnpm run preview
```

Откройте `http://localhost:4173/lesnaya-nora/`. Для разработки: `pnpm run dev`, адрес `http://localhost:5173/lesnaya-nora/`. Node.js на сервере Pages не нужен; Node 22.12 и pnpm 12.6 закреплены только для CI. Локальные глобальные установки не меняются.

Для другого адреса задайте `VITE_BASE_PATH` при сборке и проверке, например `/` для собственного домена. Значение должно начинаться и заканчиваться `/`.

Сохранения находятся в localStorage браузера. Сохранения с localhost автоматически не переносятся на github.io; это другой origin. Серверной синхронизации нет. Внешний Google Fonts используется только для оформления и имеет системные запасные шрифты.

## Если публикация не запустилась

Проверьте включение Actions в репозитории, выбор GitHub Actions в Pages, ветку `main` и отсутствие ожидающего подтверждения окружения `github-pages`. При ошибке установки проверьте закоммиченный lock-файл; при ошибке ресурсов — регистр имён (Linux различает заглавные и строчные буквы). Откройте логи задачи в Actions, исправьте причину и отправьте новый коммит. Принудительная отправка и удаление веток не требуются.

Модели кабана входят в общий реестр ModelAssets: boar.glb и boar-low.glb. Для изменения исходника используйте tools/art/BoarAsset.ts и pnpm run models -- boar, затем добавьте оба GLB в коммит. Сборка автоматически включит их в версионированный manifest. Текстура загрязнения создаётся локально как общая DataTexture; внешних ссылок и дополнительных загрузок для неё нет.

Плавание и щука: `pnpm run models -- pike rabbit beaver moose boar bear wolf dog snake`. Эта команда обновляет клипы `swim` выбранных видов и оба GLB щуки, сохраняя остальные ресурсы. Новые `pike.glb` и `pike-low.glb` включены в CREATURE_NAMES и проверяются общим manifest деплоя.
